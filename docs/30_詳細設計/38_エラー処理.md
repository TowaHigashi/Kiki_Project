# 3-8. エラー処理

## 方針

現状の実装はエラーハンドリングが薄い。以下を目標方針とし、実装が進んだら本節を更新する。

- ユーザー向けには状況を壊さず伝える（とくにローディング中）
- 開発時は `console` に原因を残す
- 1 オブジェクトの失敗でシーン全体を落とさない
- 必須アセット失敗時は探索開始ゲート（要件 5.8）を通過させない、または縮退起動の方針を明示する

---

## 対象と現状 / 想定対応

| ケース | 現状 | 想定対応 |
|--------|------|----------|
| GLB 読み込み失敗 | `GLTFLoader` のエラーが未統一 | `SceneObject` で catch → 該当のみスキップ + ログ。ローディング集計へ失敗を通知 |
| 必須アセット失敗 | ゲート未実装 | LoadingOverlay で再試行 or エラーメッセージ。探索開始不可 |
| 任意アセット失敗 | 同上 | 欠落したまま探索開始可（フォールバック） |
| モデルパス不正 / ファイル未配置 | 画面上は欠落 | `path` と `public/models` の対応確認 |
| `objects.js` の id なし / 重複 | 無反応・誤動作 | 開発時の一意チェック |
| `interaction` 未定義（将来） | — | デフォルト動作（例: 何もしない / cameraOnly）にフォールバック |
| `cameraFocusIn` 空のクリック | モーダルを開かない | 仕様として許容（装飾モデル） |
| `modalComponentMap` 未定義 | 左右遷移不能 | 作品追加手順で必須化 |
| WebGL 非対応・初期化失敗 | 未処理 | 非対応メッセージを DOM に表示 |
| 動画・外部リンク失敗 | スタブ | 埋め込み失敗時の代替 UI（5.2 / 5.4） |
| BGM 読込失敗 | 未実装 | 無音で継続、トグル無効化など（5.3） |
| テクスチャ / HDR 失敗 | 未整備 | フォールバック色・環境光のみ |

---

## ローディングとの関係（要件 5.8）

```text
読込エラー
  ├─ 必須失敗 → 開始不可 + エラー表示 / 再試行
  └─ 任意失敗 → 進捗完了扱い + 警告ログ → Start / Explore へ
```

必須 / 任意の区分はデータ側（例: `objects.js` のフラグ）またはローダー設定で定義する。

---

## API 通信

本システムは現状、外部 API に依存しない。追加する場合はタイムアウト・リトライ・ユーザー向けエラー表示を本節に追記する。
