# 設計方針

## 1. データ駆動設計

本システムでは、3Dオブジェクトに関する情報を `src/data/objects.js` に一元管理する。

作品やオブジェクトを追加する際は、Three.js の実装を直接変更するのではなく、`objects.js`（および必要に応じて `modalComponentMap.js`・モーダル Vue）に定義を追加・変更することで対応できる構成とする。

インタラクション種別（5.5）、カメラ演出（5.6）、オブジェクト演出・時間演出・BGM 切替（5.9）なども可能な限りデータ側に持ち、設定変更で差し替えられるようにする。

これにより、作品追加時の影響範囲を最小限に抑え、保守性および拡張性を向上させる。

---

## 2. 状態管理

画面全体で共有する状態は Pinia（Store）で管理する。

Three.js と Vue コンポーネント間の状態共有は Store を介して行い、直接相互参照は行わない。

ローディング・スタート・モーダル・メニュー・設定・ヘルプ・散策・演出再生・サウンド設定など、画面モードや設定に関わるフラグも Store に集約し、UI と描画が同じ状態を参照する。

---

## 3. Three.js の責務

Three.js は描画・空間内表現に関する責務を担当する。

- シーンの描画
- カメラ制御・カメラ演出（5.6）
- ライト管理
- Raycaster による当たり判定
- オブジェクト演出・時間経過演出（5.9）
- アセット読み込みの進捗通知（5.8）

UI の表示・非表示やメニュー／設定などのユーザーインターフェースは Vue が担当する。

---

## 4. Vue コンポーネントの責務

Vue コンポーネントは画面表示およびユーザーインターフェースを担当する。

| 領域 | 要件 | 例 |
|------|------|----|
| ローディング / スタート | 5.8 / シナリオ | LoadingOverlay, StartPage |
| 作品詳細の表示枠 | 5.10 / 5.2 | モーダル（ObjectInfoPanel） |
| メニュー・設定・ヘルプ・クレジット | 5.10 / 5.11 | Menu, Settings, Help |
| 探索補助 | 5.7 | ヒント表示など |
| サウンド操作 UI | 5.3 / 5.11 | `SoundSetting`（音量）。BGM ON/OFF は未実装 |

Three.js の描画ロジックやオブジェクト生成は持たず、必要な状態は Store を介して取得する。

---

## 5. イベント駆動設計

ユーザー操作を起点として状態を更新し、その状態変化に応じて各コンポーネントが動作する構成とする。

オブジェクト種別ごとの分岐も「イベント → データ参照 → 対応アクション実行」の形に揃え、インタラクション（5.5）と演出再生（5.9）を追跡しやすくする。

---

## 6. 責務分離

| 層 | 責務 |
|----|------|
| Three.js | 描画・カメラ・空間演出 |
| Vue | UI（メニュー / 設定 / モーダル等） |
| Store | 状態・設定値 |
| Data | 配置・カメラ・インタラクション・演出定義 |
| Sound | 環境音 / スクリーン動画再生（5.3）。状況 BGM 切替は将来（5.9） |
| Composable | 機能の共通化 |

要件上の分け方（作品閲覧 / 体験表現 / 操作・導線）は `10_要件定義.md` §5 冒頭を正とする。

---

## 7. ローディングをゲートにする

要件 5.8 に従い、主要アセットの読み込み完了前は探索を開始しない。

読み込み進捗は UI に表示し、完了後にスタート（または直接探索）へ進む。失敗時は `38_エラー処理.md` に従う。
