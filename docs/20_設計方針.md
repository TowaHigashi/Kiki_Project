# 設計方針

## 1. データ駆動設計

本システムでは、3Dオブジェクトに関する情報を `src/data/objects.js` に一元管理する。

作品やオブジェクトを追加する際は、Three.js の実装を直接変更するのではなく、`objects.js`（および必要に応じて `modalComponentMap.js`・モーダル Vue）に定義を追加・変更することで対応できる構成とする。
※インタラクション種別・カメラ演出・遷移先なども可能な限りデータ側に持ち、オブジェクトごとに異なる動作（要件 5.5 / 5.6）を設定変更で差し替えられるようにする。

これにより、作品追加時の影響範囲を最小限に抑え、保守性および拡張性を向上させる。

---

## 2. 状態管理

画面全体で共有する状態は Pinia（Store）で管理する。

Three.js と Vue コンポーネント間の状態共有は Store を介して行い、直接相互参照は行わない。

ローディング完了・スタート可否・モーダル・散策など、画面モードに関わるフラグも Store（または専用 Store）に集約し、UI と描画が同じ状態を参照する。

これにより、各コンポーネントの責務を明確化し、依存関係を最小限に抑える。

---

## 3. Three.js の責務

Three.js は描画処理に関する責務のみを担当する。

主な責務は以下のとおりである。

- シーンの描画
- カメラ制御・カメラ演出
- ライト管理
- Raycaster による当たり判定
- オブジェクト演出・アニメーション更新
- アセット読み込みの進捗通知（ローディング連携）

UI の表示・非表示や画面遷移などのユーザーインターフェースは Vue が担当する。

---

## 4. Vue コンポーネントの責務

Vue コンポーネントは画面表示およびユーザーインターフェースを担当する。

- ローディング表示（要件 5.8）
- スタート画面（利用シナリオ）
- 操作案内・探索補助ナビ（要件 5.7）
- モーダル・外部リンク・サウンド UI（要件 5.2〜5.4）

Three.js の描画ロジックやオブジェクト生成などの処理は持たず、必要な状態は Store を介して取得する。

これにより、表示ロジックと描画ロジックを分離し、保守性の高い構成を実現する。

---

## 5. イベント駆動設計

ユーザー操作を起点として状態を更新し、その状態変化に応じて各コンポーネントが動作する構成とする。

例えば、オブジェクト選択時はクリックイベントを起点として Store を更新し、その状態を監視するコンポーネントがカメラ移動や UI 表示を行う。

オブジェクト種別ごとの分岐も「イベント → データ参照 → 対応アクション実行」の形に揃え、処理の追跡や機能追加を容易にする。

---

## 6. 責務分離

各モジュールは単一の責務を持つことを原則とする。

- Three.js：描画・演出
- Vue：UI
- Store：状態管理
- Data：設定情報（配置・カメラ・インタラクション種別）
- Composable：機能の共通化

各モジュールは必要最小限の依存関係で連携する構成とする。

---

## 7. ローディングをゲートにする

要件 5.8 に従い、主要アセットの読み込み完了前は探索を開始しない。

読み込み進捗は UI に表示し、完了後にスタート（または直接探索）へ進む。失敗時は全体を落とさず、エラー処理方針（`38_エラー処理.md`）に従う。
