# 開発ルール

## 1. 言語・構成

- 言語は **JavaScript**（TypeScript は未採用）
- Vue は `<script setup>` を用いる
- ルータ（vue-router）は使用しない。画面切替は Store のフラグで表現する

## 2. 責務の境界

| 層 | 置いてよいこと | 置いてはいけないこと |
|----|----------------|----------------------|
| `components/three` / composables | 描画・カメラ・Raycaster・空間演出・読込進捗通知 | メニュー文言・設定フォーム |
| `components/ui` / `modal` | UI（モーダル / メニュー / 設定 / ヘルプ / ローディング） | Three.js のシーン生成 |
| `stores` | 共有状態・設定値 | 重い描画ロジック |
| `data` | 静的設定（オブジェクト・遷移・インタラクション・演出） | 実行時の副作用 |

Three.js と Vue を直接つなぐ場合は、必ず **Pinia（sceneStore）** を介す。

要件の責務分け（5.1〜5.11）は `10_要件定義.md` を正とする。とくに:

- 演出の中身 → 5.9（データ + Three / Sound）
- モーダル枠 → 5.10、中身 → 5.2
- 設定項目 → 5.11、設定 UI → 5.10

## 3. データ追加の手順（作品・オブジェクト）

1. `src/data/objects.js` にエントリを追加する（`id` は config=`1xxx`、クリック対象=`2xxx`、装飾モデル=`21xx`）
2. クリックで寄らせる場合は `cameraFocusIn` / `cameraFocusOut` を埋める
3. インタラクション種別・演出がある場合はデータ側に定義する（`34_データ設計.md`。拡張予定）
4. モーダル左右移動が必要なら `src/data/modalComponentMap.js` を更新する
5. 詳細パネルが必要なら `components/modal/SubComponent{n}/` に Vue を追加し、`ObjectInfoPanel.vue` の `switch` に紐づける
6. `SceneCanvas.vue` で `SceneObject` を配置する（将来は `v-for` 化予定）
7. 新規アセットはローディング対象（5.8）に含める

**Three.js のコア実装を直接いじらず、データとパネル追加で拡張することを原則とする。**

## 4. Store の扱い

- Store は現状 `sceneStore` のみ
- 状態の更新は各モジュールから直接代入してよい（setup store の `ref` を公開している）
- 新しい共有フラグ（ローディング、メニュー、設定、ヘルプ、演出再生、音量など）が必要になったら、まず Store に追加し、UI / Three 側は Store を監視する

## 5. 命名・ファイル

- コンポーネントは PascalCase（例: `SceneCanvas.vue`、`SubComponent2.vue`）
- composable は `useXxx.js`
- データ定義は `objects.js` / `modalComponentMap.js`（`.ts` ではない）
- テスト・廃止予定ファイル（`*test.vue`、`CameraController.js` など）は新規参照しない

## 6. ドキュメント

- 要件の正は `docs/10_要件定義.md`（5.1〜5.11）
- 体験フローの正は `docs/30_詳細設計/35_イベント設計.md` および `36_状態遷移.md`
- 実装と設計がずれたら、**先に docs を更新してから**大きなリファクタに入る
